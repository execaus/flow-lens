# Flow Lens

Панель в правой боковой колонке Orca ADE. Показывает последний структурированный план, который агент опубликовал в текущей рабочей области. В списке видны этапы, их статусы и число выполненных шагов. Если открыто несколько сессий, выберите нужную в панели.

## Установка

1. В Orca откройте **Settings → Plugins → Install plugin → Git URL**.
2. Вставьте `https://github.com/execaus/flow-lens.git#v0.1.1`, проверьте разрешения и включите плагин.
3. Откройте **Flow Lens** справа от терминала и выберите сессию агента, если их несколько.
4. Нажмите **Подключить файл плана**. Скопируйте инструкцию из панели в выбранную сессию. Агент запишет план и будет обновлять его по ходу работы. Встроенный инструмент планирования для этого не нужен.

## Где хранится план

По умолчанию Flow Lens создаёт каталог во временной папке ОС и подставляет абсолютный путь в инструкцию для выбранной сессии. Агенту и worker Orca нужен доступ к одному и тому же пути. Плагин обновляет панель при изменении файла. При штатной остановке worker временные папки удаляются. После перезапуска worker подключите файл заново и передайте агенту новую инструкцию.

Если песочница агента разрешает запись только в рабочей папке, добавьте строку `/.flow-lens/` в локальный файл исключений. Команда ниже выполняется из корня рабочего дерева, в котором запущен агент:

```sh
printf '\n/.flow-lens/\n' >> "$(git rev-parse --git-path info/exclude)"
```

В панели нажмите **Использовать папку проекта** и передайте агенту обновлённую инструкцию с новым путём. Плагин проверяет, что Git игнорирует каталог, JSON и промежуточный файл, прежде чем подготовить путь. Правило хранится в локальных настройках Git, а общий `.gitignore` остаётся прежним. Запасной режим доступен для локальной папки Git. Когда план в ней больше не нужен, его можно удалить.

Файл содержит `{"version":1,"steps":[{"title":"Название этапа","status":"in_progress"}]}`. Статусы шагов — `pending`, `in_progress` и `completed`. При невалидном JSON панель сообщает об ошибке и сохраняет последний корректный план. Плагин сопоставляет файл с ID сессии, если Orca его сообщает, или с терминалом, пока ID недоступен.

Планы из `update_plan` (Codex) и `TodoWrite` (Claude Code) по-прежнему поддерживаются через `agent.tool.after`, когда Orca передаёт эти события. Переписку и вывод терминала плагин не читает. На SSH и WSL Orca v1.4.259 не передаёт хуки инструментов агентов.

## Локальная разработка

Минимальная версия Orca по манифесту — `1.4.248`, где появился `contributes.hooks`. Для проверки интеграции используйте версию `1.4.259`, по документации которой написан плагин. Orca загружает TSX напрямую, поэтому отдельная сборка и установка npm-пакетов не нужны.

1. В Orca откройте **Settings → Plugins → Development folders…** и добавьте папку `flow-lens`, в которой лежит `orca-plugin.json`. Если система плагинов выключена, включите её в **Settings → Plugins**.
2. Проверьте экран разрешений. Плагин запрашивает профиль `trusted-worker` для хука `agent.tool.after`, `workspace:read` для определения текущей рабочей области и `agent:read` для сопоставления событий с сессиями. Одобрите плагин в Orca.
3. Откройте рабочую область с локальным агентом, затем **Flow Lens** в правой боковой колонке. Подключите файл плана и попросите агента сменить статус одного из этапов. Проверьте, что подсветка текущего шага и счётчик меняются, а файл не появляется в `git status`. При наличии нескольких сессий проверьте, что они показывают разные планы.

Из корня плагина с доступным CLI:

```sh
orca plugin validate .
orca plugin inspect .
orca plugin dev load .
```

Если загрузка вернёт `approval_required`, проверьте указанные разрешения и подтвердите их в Orca или повторите команду с выданным `--approve <fingerprint>`. На открытой рабочей области панель можно показать командой `orca plugin open local.flow-lens --panel flow`. Для отладки используйте `orca plugin logs local.flow-lens`.

## Первый выпуск

Для первого выпуска проекта или его форка выполните команды из папки `flow-lens` после локальных проверок. Подставьте владельца и имя пустого репозитория GitHub:

```sh
git add .gitignore README.md orca-plugin.json src/
git diff --cached --name-status
git commit -m "Release Flow Lens v0.1.0"
git tag -a v0.1.0 -m v0.1.0
git remote add origin https://github.com/OWNER/REPO.git
git push -u origin main
git push origin v0.1.0
```

В коммите должны быть `orca-plugin.json` и все файлы из `src/`. Orca использует их напрямую. После отправки тега откройте **Settings → Plugins → Install plugin → Git URL** и вставьте `https://github.com/OWNER/REPO.git#v0.1.0`.

Для следующей версии обновите поле `version` в манифесте, например до `0.1.1`, повторите проверки, закоммитьте файлы, создайте тег `v0.1.1` и отправьте коммит и тег. Установите обновление через тот же пункт, указав `https://github.com/OWNER/REPO.git#v0.1.1`.

Для приватного репозитория Git на машине, где работает Orca, должен иметь доступ к репозиторию. Проверьте его на этой машине командой `git ls-remote --exit-code https://github.com/OWNER/REPO.git refs/tags/v0.1.0`.
