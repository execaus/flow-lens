# Flow Lens

Панель в правой боковой колонке Orca ADE. Показывает последний структурированный план, который агент опубликовал в текущей рабочей области. В списке видны этапы, их статусы и число выполненных шагов. Если открыто несколько сессий, выберите нужную в панели.

## Установка

1. В Orca откройте **Settings → Plugins → Install plugin → Git URL**.
2. Вставьте `https://github.com/execaus/flow-lens.git#v0.1.0`, проверьте разрешения и включите плагин.
3. Откройте **Flow Lens** справа от терминала и попросите агента создать план встроенным инструментом.

## Откуда берётся план

Агент составляет план с учётом переписки и рабочей области. Flow Lens слушает событие Orca `agent.tool.after` и обрабатывает полные списки этапов из `update_plan` (Codex) и `TodoWrite` (Claude Code). Статус шага берётся из плана агента. Для проверки попросите агента: «Составь план из трёх шагов через встроенный инструмент планирования и обновляй статусы по мере работы».

В этой версии плагин принимает обновления только для рабочей области в фокусе, когда Orca указывает терминал агента. План хранится в памяти worker и исчезает после его перезапуска. Если Orca сообщает ID сессии, плагин проверяет его перед показом плана. Если ID отсутствует, план привязан к терминалу. Панель показывает только планы, опубликованные после включения плагина. Переписку и прокрутку терминала плагин не читает, вызовы инструментов не блокирует. Если агент описал план только в сообщении, включите подходящий инструмент планирования и попросите агента опубликовать план повторно.

Поддержка форматов проверяется отдельно от доставки событий. Orca и версия агента должны передавать вызов нужного инструмента в `agent.tool.after`. Это ещё предстоит проверить в приложении. Пошаговые операции Claude `TaskCreate` и `TaskUpdate` в этой версии не обрабатываются. На SSH и WSL Orca v1.4.259 не передаёт хуки инструментов агентов.

## Локальная разработка

Минимальная версия Orca по манифесту — `1.4.248`, где появился `contributes.hooks`. Для проверки интеграции используйте версию `1.4.259`, по документации которой написан плагин. Orca загружает TSX напрямую, поэтому отдельная сборка и установка npm-пакетов не нужны.

1. В Orca откройте **Settings → Plugins → Development folders…** и добавьте папку `flow-lens`, в которой лежит `orca-plugin.json`. Если система плагинов выключена, включите её в **Settings → Plugins**.
2. Проверьте экран разрешений. Плагин запрашивает профиль `trusted-worker` для хука `agent.tool.after`, `workspace:read` для определения текущей рабочей области и `agent:read` для сопоставления событий с сессиями. Одобрите плагин в Orca.
3. Откройте рабочую область с локальным агентом, затем **Flow Lens** в правой боковой колонке. Попросите агента опубликовать и затем обновить план. Проверьте, что подсветка текущего шага и счётчик выполненных шагов меняются. При наличии нескольких сессий убедитесь, что они показывают разные планы. Повторите проверку с каждым агентом, поддержку которого укажете в релизе.

Из корня плагина с доступным CLI:

```sh
orca plugin validate .
orca plugin inspect .
orca plugin dev load .
```

Если загрузка вернёт `approval_required`, проверьте указанные разрешения и подтвердите их в Orca или повторите команду с выданным `--approve <fingerprint>`. На открытой рабочей области панель можно показать командой `orca plugin open local.flow-lens --panel flow`. Для отладки используйте `orca plugin logs local.flow-lens`.

## Первый выпуск

Для первого выпуска проекта или его форка выполните команды из папки `flow-lens` после локальных проверок. Подставьте владельца и имя пустого репозитория GitHub:

```sh
git add .gitignore README.md orca-plugin.json src/
git diff --cached --name-status
git commit -m "Release Flow Lens v0.1.0"
git tag -a v0.1.0 -m v0.1.0
git remote add origin https://github.com/OWNER/REPO.git
git push -u origin main
git push origin v0.1.0
```

В коммите должны быть `orca-plugin.json`, `src/worker.mjs` и `src/panel.tsx`. Orca использует эти файлы напрямую. После отправки тега откройте **Settings → Plugins → Install plugin → Git URL** и вставьте `https://github.com/OWNER/REPO.git#v0.1.0`.

Для следующей версии обновите поле `version` в манифесте, например до `0.1.1`, повторите проверки, закоммитьте файлы, создайте тег `v0.1.1` и отправьте коммит и тег. Установите обновление через тот же пункт, указав `https://github.com/OWNER/REPO.git#v0.1.1`.

Для приватного репозитория Git на машине, где работает Orca, должен иметь доступ к репозиторию. Проверьте его на этой машине командой `git ls-remote --exit-code https://github.com/OWNER/REPO.git refs/tags/v0.1.0`.
